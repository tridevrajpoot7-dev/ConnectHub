# ConnectHub — What I Changed

## 🚨 Critical fix: real authentication
Previously, the server trusted whatever `userId` the client sent in a
header/body/query param — meaning anyone could act as any user (or
admin) just by knowing/guessing their numeric ID. No password was
re-checked after the initial login.

**Now:**
- `/api/login` and `/api/signup` issue a signed token (HMAC-SHA256,
  using Node's built-in `crypto` — no new dependency).
- Every sensitive route now verifies that token via `requireAuth`,
  and checks `requireSelfOrAdmin` so a user can only act on their
  own data (unless they're an admin).
- `/api/support` (list/update/delete) and `/api/admin/support` now
  require an authenticated **admin** — previously anyone could read
  every user's support messages (names + emails) with no login at
  all.
- The frontend now stores this token in `localStorage` on
  login/signup, and every page has a small injected script that
  automatically attaches it to every `/api/...` request.

## 🔑 .env
Your old MongoDB username/password were sitting in plaintext in the
zip you uploaded. I replaced it with a placeholder — **you need to:**
1. Rotate the password in MongoDB Atlas (the old one should be
   treated as compromised since it was in an uploaded file).
2. Put the new connection string into `.env` → `MONGODB_URI=`.
3. A fresh random `SESSION_SECRET` has already been generated for
   you in `.env` — keep it secret, don't commit it.

## What I verified
- `node --check` passes on `server.js`, `script.js`, and every
  inline `<script>` block in all 14 HTML pages — no syntax errors.
- Server boots, loads `.env`, and reaches the MongoDB connection step
  without crashing on the new auth code.

## What I could NOT verify
- I have no internet access in this environment, so I could not
  actually connect to your MongoDB Atlas cluster or click through
  the UI end-to-end. **Please test the full login → post → follow →
  message flow yourself** after rotating your DB password and
  running `npm install` (node_modules was intentionally left out of
  this zip — it's regenerated by `npm install` and shouldn't be
  committed/shared anyway).

## Smaller things not yet done (lower priority)

  but you'll want real image upload/storage for production.
- No rate limiting on login/signup (brute-force protection).
- No automated tests.
